# ⏳ Await

一款简洁优雅的 Android **倒数日**应用。支持 **软件通知、Telegram、ntfy** 三种通知渠道，可单选或同时开启多个。软件通知在手机发送，Telegram / ntfy 由服务器定时推送。

## ✨ 功能特性

### 📅 倒数日管理
- 新建 / 编辑 / 删除倒数日日程（**左滑即删，带撤销**）
- 大字号倒计时展示：**还有 N 天 / 就是今天 / 已过去 N 天**
- 日程备注、标记颜色、置顶
- 循环周期：按天 / 周 / 月 / 年，支持「每隔 N 个单位」
- 分组浏览：置顶 / 今天 / 即将到来 / 已经过去
- **独立管理分组**：可以先建好空分组再往里放日程，新建/编辑日程不再是唯一入口
- **批量分配分组**：多选或全选日程，一次性归到某个分组，或整批移出分组
- **分组批量管理**：多选 / 全选删除分组，可选择「仅移出分组」或「连同日程一起删除」，默认分组（未分组）同样可清空
- 全文搜索

### 🔔 多渠道通知
- 「通知设置」勾选软件通知 / Telegram 通知 / ntfy 通知，可任选一种或任意组合；所有日程共用渠道设置
- 任意已开启的通知渠道可用后，首页不再显示通知提示栏；各渠道的详细状态仍可在「通知设置」查看
- 软件通知无需服务器和网络，支持提前提醒、周期循环、重启恢复；重新开机补发最近 24 小时内已安排的提醒
- Android 13+ 需允许通知权限；Android 12+ 允许精确提醒后按指定分钟调度，未授权时使用系统非精确提醒，可能延迟
- 同一天、同一时刻的日程也分别发送消息；每条日程在所选渠道中独立通知
- 「通知设置」统一设置默认通知时间，初始为 09:00；修改后自动重排本机提醒，并联网同步云端
- 日程编辑页新增「精准时间」开关，默认关闭；开启后才可自定义时刻，关闭后继续跟随默认时间。软件 / Telegram / ntfy 使用同一有效时刻
- 升级到 v2.4.0 后，已有日程全部关闭精准时间并跟随默认时刻；需要单独时刻的日程可重新开启
- 软件通知为普通系统通知，不持续响铃，也不显示全屏提醒；手机关机或应用被强行停止时无法通知，重新打开后恢复调度
- Telegram / ntfy 由服务器发送，手机关机后仍会推送已同步日程；新增、编辑、删除、导入和渠道选择联网后自动同步
- 多级提前提醒、分钟级提醒时刻、按日 / 周 / 月 / 年循环在各渠道中保持一致
- 服务端按渠道保存发送记录并分别重试，一个渠道失败不会重复发送另一个渠道的成功通知
- 「云端部署配置」先验证 Await 服务地址、访问权限、服务版本和手机绑定；通过后再配置云端渠道
- 在手机填写 Telegram Bot Token / Chat ID、ntfy 地址 / Topic / 可选 Token，支持测试填写的参数并保存到云端；服务器加密保存凭据，不回显 Token、不进入手机备份
- Telegram / ntfy 未配置前无法勾选开启；软件通知独立使用，已有云端配置可继续正常提醒
- 新安装默认软件通知；从已有 Telegram 服务端版本升级时保留 Telegram 选择，不自动多开渠道

云端通知先部署或升级 [通知服务端](server/README.md)，手机「云端部署配置」验证连接后，在「通知设置」填写云端渠道参数，再勾选、保存并测试。仅软件通知无需部署服务器。关闭云端渠道需同步成功才会取消服务器待发提醒；离线时仍按上次同步的设置推送。旧版仅 Telegram 服务器需升级后才能同步新的渠道选择。升级到 v2.3.1 后，每条日程独立通知，原「合并通知」入口和设置已移除；旧备份仍正常恢复日程与普通分组。云端服务也需升级，旧合并队列会自动拆分，已发送记录继续保留。

### 📥 导入日程（独立板块）
- **粘贴 JSON**：不必先存成文件，直接粘贴文本；外面裹的 ``` 代码块和前后多余的说明文字会被自动剥掉
- **从文件导入**：读取 Await 的备份文件，或任何符合格式的 JSON
- **AI 迁移助手**：内置一段现成提示词，一键复制后连同旧应用的截图发给 AI，把返回的 JSON 粘回来即可完成搬家
- **宽松格式**：接受裸数组、可省略 id 与大部分字段；日期直接写 `"date": "2026-10-01"`，不必换算 epoch day
- **导入方式可选**：合并（同 id 以备份为准）或覆盖（清空后导入）

### 💾 云端备份与恢复
- 备份复用「云端部署配置」中的 Await 地址和访问密钥，无需另配 WebDAV 或网盘账号
- Docker 部署时可选择开启备份，默认关闭；设置 `AWAIT_BACKUP_ENABLED=true` 后启动或重建服务，手机重新验证连接
- **立即备份 / 历史恢复 / 恢复最新备份**：保存完整日程、备注、颜色、置顶、空分组，恢复前选择合并或覆盖
- 备份保留各日程的精准时间开关及默认通知时间；覆盖导入恢复备份的默认时间，合并导入沿用本机默认时间。云端备份服务需一起升级到 v2.4.0
- **定时上传**：每天 / 每 3 天 / 每周 / 每月 + 指定时刻，可限定仅 WLAN；后台任务由 WorkManager 执行，网络错误会有限重试
- **保留历史**：5 / 10 / 20 / 50 份，下次备份时清理超出的旧版本；同一秒多次备份不会覆盖
- 服务器以 AES-256-GCM 加密备份，保存在原有 `schedule_data` 数据卷，重建容器不丢失；关闭备份开关不会删除历史
- 手机关机或后台受限时上传可能延迟，启动后补做逾期备份；服务器保存的备份始终是手机上一次成功上传的完整数据
- 本地 JSON 导出和文件导入保留，旧 WebDAV 的 JSON 文件可以下载后导入；升级后需重新开启定时备份，不会自动改写旧备份盘
- 备份中不包含服务器访问密钥、Telegram Bot Token 或 ntfy Token

与云端通知使用同一套 [Docker 服务](server/README.md)。部署指引提供「部署时开启云端备份」选项，复制的命令需在服务器执行；执行后手机重新验证，进入「备份与恢复」即可使用。已绑定旧手机的服务器可用同一访问密钥连接新手机恢复备份，上传和通知同步需先迁移绑定。

## 🛠 技术栈

| 项目 | 选型 |
|---|---|
| 语言 | Kotlin 2.0 |
| UI | Jetpack Compose + Material 3（支持动态取色） |
| 架构 | MVVM（ViewModel + StateFlow） |
| 存储 | Gson + SharedPreferences（轻量数据） |
| 提醒 | Android AlarmManager 软件通知；Python + SQLite 服务端 Telegram / ntfy 推送 |
| 日程同步 | HTTPS + WorkManager，断网重试 |
| 备份 | Await 云端备份 API + SQLite 加密历史，复用 HTTPS 连接 |

## 📦 构建

```bash
cd Await
./gradlew assembleDebug      # 调试版
./gradlew assembleRelease    # 正式版（需签名配置）
```

要求：JDK 17+，Android SDK 34。

### 🔑 正式签名配置

正式版需要签名密钥。在项目根目录创建 `keystore.properties`（已被 `.gitignore` 排除，不会提交）：

```properties
storeFile=keystore/await-release.keystore   # 密钥库路径
storePassword=你的密钥库密码
keyAlias=你的别名
keyPassword=你的密钥密码
```

生成新密钥库：

```bash
keytool -genkeypair -v -keystore keystore/await-release.keystore \
  -alias await -keyalg RSA -keysize 2048 -validity 10950
```

> ⚠️ 请妥善备份 `keystore.properties` 和密钥库文件。丢失后无法为已安装用户推送升级。
